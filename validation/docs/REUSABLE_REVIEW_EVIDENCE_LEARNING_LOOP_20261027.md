## 目的・既存仕様との関係

「施設を一件確認して終了」ではなく、**レビューの原因、証拠、判断可能範囲、改善可能な検査、再審査条件**を再利用可能なケースとして保全する。全国の全地点について、敷地や入口の人間確認が不要になると約束しない。

- 共通安全規則は [root AGENTS.md](../../AGENTS.md)、C独立検証は [C AGENTS.md](../AGENTS.md) が正本。既存の [江戸川区レビュー・パケット](EDOGAWA_HUMAN_REVIEW_PACKET_PROTOCOL_20261019.md) と [委任手順](EDOGAWA_DELEGATED_REVIEW_HANDOFF_20261019.md) における原本固定・human review・後段HOLDを維持する。
- 今回の出発点は [市川実OSM証拠記録](../reviews/2026-10-27-ichikawa-osm-four-site-research-gate.md)、[研究Issue #328](https://github.com/1kz-ma1/HINANEX/issues/328) および [C独立レビューIssue #333](https://github.com/1kz-ma1/HINANEX/issues/333)。4施設周辺の37 OSM地物は**未割当の調査ヒント**であり37の避難施設ではない。
- 公式指定、敷地・建物、入口、災害別利用条件、現在の開設状況、経路は**別々の検証対象**とする。原本整合性のPASSから別の項目のPASSを伝播しない。

## 1. 証拠から改善までのループ（CURRENT / FUTURE）

1. **Aが原本取得・保全（既存）**：ソースURL・提供者・原本バイト/ハッシュ・取得時刻・資料が主張する更新/適用時点・許諾/出典・範囲を記録。取得失敗と0件は区別する。原本のバイトはGit管理外。
2. **機械的な照合・候補生成（部分的に既存）**：SHA・構造・原文ID・決定論的な形式検証、位置の「観測値による近傍ヒント」を記録。近さ・名称・OSMタグから同一施設や入口を自動確定しない。
3. **C/委任班員が事実を独立に照合（レビュー依頼中）**：原本と別の信頼できる一次資料に照らし、対象の**個別属性**の判断、矛盾、未確認、対象時点を明示する。AI支援を受けた場合、使用範囲と人が実際に照合した範囲を区別。
4. **レビュー記録の受領・監査（運用設計）**：レビュアーが提出したケースを、オーナーが根拠とレビュー範囲に限定して採否判断。自己申告名は本人確認の証明ではない。結果の構造検証はC正式承認ではない。
5. **パターン分類 → 回帰テスト候補（今後の運用）**：「なぜ自動判定できなかったか」を失敗モードと反例として抽出。安全な決定論的検査、UNKNOWNへの自動保留、追加資料要求のどれに活用できるかを区別する。
6. **別PRで評価（FUTURE）**：個別の改善ルールは、別の自治体/別ソース版を含む正例・負例・欠損例で検証し、C独立確認と必要な契約審査を経て採用する。レビューケースそのものをDやGISへ自動投入しない。
7. **再審査（FUTURE運用）**：ソースhash/版、公式指定の時点、施設の移転、再編、入口/運用、災害別の条件、取得仕様が変わった場合は過去の承認をそのまま流用しない。該当属性を失効・UNKNOWNへ戻し、対象範囲を再確認する。

## 2. 記録単位と最小スキーマ（文章・非実行契約）

**1ケース = 1つの原本版 × 1つの出力/施設候補/個別属性 × 1つの検証命題**。施設名をキーにせず、不変の `case_id` と元の source feature key / OSM `type+id` 等を保持する。採否は**属性別**で、施設単位の包括承認を持たせない。

| 項目 | 必須で記録する意味 |
| --- | --- |
| `case_id`, `review_scope`, `assertion` | 固有ID、確認対象の範囲、検証する具体的な命題（例: 「GSI index571 と OSM way X は同じ敷地か」）。 |
| `source_ids`, `source_urls`, `raw_sha256` | 原本の出典・不変識別子・ハッシュ。未取得は推測せず `UNKNOWN`。複数原本は別のハッシュを残す。 |
| `captured_at`, `source_version_or_asof`, `reviewed_at` | 取得、資料の適用時点（判明時のみ）、レビュー実施時点を混同しない。 |
| `original_claim`, `derived_observation` | 原本の値と、解析・近接候補などの機械的観測を分離する。 |
| `independent_primary_evidence` | 公式/管理者URL、資料名、版/更新日が確認できる場合の値、ページ/行/施設図の箇所。取得・閲覧の証跡。 |
| `review_disposition`, `review_reason` | `CONFIRMED` / `UNRESOLVED` / `REJECTED_CANDIDATE` / `NOT_REVIEWED`。これらは**指定範囲の照合結果**であって災害時安全認定ではない。否定には明確な反証が必要。 |
| `unknowns`, `conflicts`, `limitations` | 未知、相違、残る疑義、スコープ境界。候補0、座標なし、原本期限切れを「施設不在」としない。 |
| `reviewer_record`, `ai_assistance`, `owner_decision` | 実際に確認した人・日付・AI利用範囲・オーナーの採否。実名や私的情報は公開Gitに書かない。本人認証/承認の記録は別に保持。 |
| `failure_mode_tags`, `regression_proposal` | 誤名寄せ、広域敷地、敷地内の部分指定、正式ID欠落、入口不明、移転/時点相違など。改善仮説と、その反例・テスト条件。 |
| `recheck_triggers`, `recheck_status` | どの原本や条件の変更時に再審査するか。開始状態は未審査・HOLD。 |
| `publication_gate` | デフォルト `HOLD`、`navigation_allowed=false`、`human_c_approved=false`、`navigation_endpoint=null`。例外をこの文書・レビューパケットだけで解除しない。 |

**取り扱い**：レビュー用の具体的な原本・応募者/担当者情報・派生一覧・個人名・原本ZIP・照合結果JSONはGit管理外のアクセス制限領域で保存。Git上の長期記録はケースID、仕様、出典リンク、SHA、一般化した問題類型、未承認状態、必要なテストのみに限定。利用規約・保存期間に従い原本を安全に保存する。レビュー用の原文と機密資料をAI学習用に無断再利用しない。

## 3. 自動化可能な範囲と禁止の境界

| 機械処理・レビュー省力化候補 | 独立の裏付けがなければ自動承認できないこと |
| --- | --- |
| 同一原本内で仕様上明記された識別子の形式・一意性・紐付け検査 | 別ソースのGSI/市/OSM施設が同じ物理敷地であるという断定 |
| SHA、スキーマ、候補/欠損/差分の機械分類 | 公式指定場所の敷地境界・校庭/校舎など一部分の指定 |
| 同じ失敗モードの検出、レビューへの優先度付け、追加で必要な根拠資料の案内 | 最新の開設、災害時通行可能な入口、実際の避難経路・安全性 |
| 人間が承認した**限定属性**と原本版の整合を後日再チェック | 元の版・自治体・災害種別が違う対象への承認流用 |

レビューを単に `CONFIRMED` にするだけでは自動承認範囲は広がらない。必ず**明示された命題・出典・版・審査範囲**を検査する。AIのスコア・名前類似・300m以内・`entrance=main`・`access=yes`・公式の参考点だけで `facility_geometry_verified` や経路を昇格させない。Cが独立したソースを読む工程の代替にもならない。

## 4. 改善の受入指標（目標値は未設定）

- `review_required_count / assessed_candidate_count`：人間へ回した割合。**37 OSM地物 / 4 GSI参照点を37施設と数えない**。母数・期間・ソース種を明示する。
- `review_minutes_per_assertion`：命題ごとの実作業時間（着手・終了を別記）。
- `independently_confirmed_errors` と `false_auto_acceptances`：反証付きの誤り。安全性に関わる見逃しを単なる効率指標で相殺しない。
- `stale_or_changed_source_recheck_count`：原本改版・施設運用変化による再審査件数。
- `unknown_or_conflict_count`：未解決を独立に計数し、検査失敗/ソース不存在と混同しない。
- 比較は**同種の命題/ソース条件、別地域・別時点の保留検証データ**で行う。単発4地点の結果で「全国で何%自動化可能」と予測しない。
