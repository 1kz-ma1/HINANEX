| 項目 | 準備・確認方法 |

### 失敗時の復旧

1. 通常復旧は現在の画面で失敗表示と旧データ消去を確認して行う。F02で必要なら本人が既存の再取得を1回操作する。復帰できない場合はB1/F02中継を省略し、独立切替を口頭で伝える。
2. J01が起動できなければ、操作者が承認済みのローカル合成状況カードに切り替え、同じ合成条件・出典・UNKNOWNを説明する。合成切替は明示操作とする。
3. セッションや表示版が不明なときは現在画面を閉じ、凍結済みStage 1を新しい一時プロファイルで開始。復旧に30秒を超える見込み、または安全境界・SHAに不一致がある場合はライブ実演を停止し、承認済みのローカル録画または連番資料へ切り替える。
4. 代替資料では視聴した範囲だけを報告する。本人の操作が成立しなかった回はライブ完了として集計しない。通信や実データの許可を臨時に緩めず、次の来場者の開始前に隔離版を復元する。

## 3. 受入QAのケース

各結果に候補SHA、fixture SHA、実行環境、幅、操作と観測、証拠リンク、担当を残す。合否は `PASS / FAIL / BLOCKED / NOT_RUN`。実装側回帰、別手順・別記録の独立QA、公開境界は別の欄に記録する。以下はWP-006以降で実施する。

| ID | 操作・負例 | 合格条件 |
| --- | --- | --- |
| W5-01 | 初期状態からJ01の合成表示を明示選択。通常読込の失敗と合成読込の失敗も注入 | 合成ラベル・架空の取得状態・出典・UNKNOWNが整合。失敗で旧判断を表示せず、自動で合成へ置換しない |
| W5-02 | B1未選択・選択・解除、loopbackと不許可origin、F02で503→再取得→詳細→解除 | 未選択/不許可ではリンクなし。許可時のみ本人遷移。取得失敗と検索0件を区別し、架空の出典・未確認・座標なしを維持 |
| W5-03 | J01／F02とMJ-01の切替、戻る、再読込、次の来場者 | MJ-01は未選択と明示開始。地域、施設ID、条件、選択をURL・storage・隠れた状態で受け渡さない |
| W5-04 | J02の未選択・型不正、2条件を個別に実行 | 不正条件と暗黙開始を拒否。架空ラベル・理由・元値・出典を照合し、旧条件の結果混在なし |
| W5-05 | J04で1件、2件、3件目、解除。J05で本人未選択、比較外ID、UNKNOWNの選択 | 異なる2件が揃うまで比較不可。比較外の選択を拒否。選択時もUNKNOWN表示・安全境界を保持 |
| W5-06 | CHANGE、FAIL、END、J05→J04、それぞれに旧DOM callbackを投入 | 指定の初期状態へ戻り、旧比較・本人選択が復活しない。再開始は明示操作 |
| W5-07 | 実タブ切替、pagehide・履歴復帰、別要素のフォーカス保持 | trustedイベントを取る。非表示で状態破棄、可視復帰で適切なフォーカス。実BFCacheは `pageshow.persisted=true` を観測した場合に判定し、未観測はNOT_RUN |
| W5-08 | 320/390/1440 CSS pxごとにTab・Shift+Tab・Enter・Spaceと実AX | 水平はみ出し等で操作不可にならず、順序・可視focus・見出し・安定名と `aria-pressed` ・statusを確認 |
| W5-09 | 外部・LAN・未登録のローカル資材、DNS、プロフィール前後、終了cleanup | 対象外への成功接続なし。許可リスト以外は拒否。永続データ差分なし、専用サーバーと一時profileを回収 |
| W5-10 | 非配信パス、公開対照、切戻し、記録の復元 | 承認対象の実パスが公開用bundleに消え、公開対照バイトが維持される。別環境で読む場合はハッシュ一致。LIVEは別記録 |
| W5-11 | 7分通しを2回、そのうち1回はJ01または中継の失敗を挿入 | 7分以内に実演範囲と未実装を説明。ライブ完了と代替資料提示を区別し、復旧と終了を記録 |

必須の実演機能、外部／保存境界、旧結果の復活、安全表示、必須画面の操作性にFAILまたはBLOCKEDがあればライブ採用保留。特定環境で実BFCacheが成立しない場合はNOT_RUNのまま、復帰経路の期待状態とブロッカーを司令塔審査に出す。今回の物理端末・読み上げ端末の操作は対象外。後続の実機受入方針は [#372](https://github.com/1kz-ma1/HINANEX/issues/372) を参照する。
