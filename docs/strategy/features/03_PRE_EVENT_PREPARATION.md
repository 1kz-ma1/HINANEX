# F03 事前準備・災害時の簡易アクセス（単独機能）

- 状態: **PROPOSED UX SPEC**。2026-10-30のmainには新しいユーザー向け準備機能が統合済みとは扱わない。
- 既存試作: [E Draft PR #311](https://github.com/1kz-ma1/HINANEX/pull/311) はUI未接続の`pre_event_preparation.js` と合成テストのみ。**PRがDraft/未マージであり、本機能が使えるという主張ではない**。
- 目標: 平常時に決められることを先に任意設定し、災害時の入力や探す操作を減らす。ユーザーの避難適否を独断で決めない。

## 予定する独立体験

1. 平常時に準備メニューを開き、「保存しないでも使える」ことと端末内保存の性質・制約を説明。
2. 設計最初の対象は限定された3項目：任意の地域コード（自治体レベル）・利用階・上階へ移動できるかの**自己申告**。**氏名、住所、GPS位置、健康情報、家族/連絡先はこの初期保存スコープに含めない**。
3. 利用者の明示操作で端末内に保存し、後日自分で確認・修正・削除できる。保存が拒否/破損/失効する場合は誤って成功したと表示しない。事前設定なしでも利用可能。
4. 将来の簡易アクセス画面は、設定済み地域を手動選択の初期案として参照し、公式情報への導線・事前準備の確認を表示する。**現在災害発生中／開設中／家が安全**とは推論しない。
5. 通信不能時は保存済み情報の古さを表示し、閲覧できないライブ公式情報を「最新」と称さない。

## プライバシーと異常系

- LocalStorageは原則平文で、同一オリジンのJSからアクセス可能。本人に共有端末・保存失効・削除・バックアップ無しの制約を説明。匿名保存も個人データになり得る。
- 初期対象以外の連絡先・家族構成・詳細住所・GPS・介助要件を**勝手に追加しない**。拡張には新たなプライバシー/安全レビューと別仕様。
- 地域コードや階数は本人の自己申告であり、個々の建物の耐震性/浸水安全性や避難行動の自動指示の根拠にならない。
- 180日で要確認というPR #311案は正式な情報保証/行政更新頻度ではない。新しいUIに採用するかは実装時レビュー。

## 最小受入基準

- 未保存、明示保存、再読込、編集、削除、保存拒否/容量不足/改ざん/失効、共用端末の説明がPC・スマホで検証される。
- 公式災害情報と事前設定値を表示上も分離。意図しないネットワーク送信/URLの個人データ混入なし。
- 現行mainのGISを改変せず、合成シナリオで動作する隔離Prototypeを先に提出する。
