# F04 公式データを利用した洪水の時系列再生

- 状態: **FUTURE / API利用調査段階**。HINANEXでの時系列浸水再生、浸水ナビAPIの本番接続、公式利用許諾の確認は未実装・未完了。
- 目標: 洪水シミュレーションの専門知識がなくても、公式の**事前計算済みの仮定シナリオ**について時間変化・前提条件を直感的に理解できる。
- 候補ソース: 国交省・国土地理院「浸水ナビ（地点別浸水シミュレーション検索システム）」、[公式サイト](https://suiboumap.gsi.go.jp/)、[データ利用マニュアル候補](https://suiboumap.gsi.go.jp/pdf/Data-riyo_manual.pdf)。資料URL/最新版/利用規約/レスポンス/CORSは**班員が必ず実際に確認**し、確認できなければUNKNOWN。候補ソースは採用決定ではない。

## 独立した体験

1. 地域/地点を選択（地図クリック又は許可されたGPS、拒否時に手動操作可能）。
2. 対応する河川、想定破堤点、公式計算条件、時系列の対象範囲/時間を、取得できた事実に基づき提示。複数の条件をまとめて1つの実際の洪水と誤認させない。
3. 再生・停止・時間スライダーにより**公式シナリオでの**浸水の広がりを表示。色の凡例、時刻の相対基準、地点の浸水深データが無い状態を別に示す。
4. 参照元、想定条件、作成時点、範囲、制限、「これは現在の洪水のリアルタイム予測ではない」という説明を確認できる。
5. 避難施設情報に接続せずに単独完了。F05から任意で他機能へ進める。

## 段階別スコープ

- T-0 技術調査：公式仕様、対象河川/地区/破堤点/時系列タイルや地点の浸水深などの実際のデータ種、時刻・座標系・凡例、取得制限、CORS、認証、URL権利/再配布、最新の運用、利用者位置情報の外部送信を**項目別に確認**。
- T-1 機能から切り離したPrototype：1地域・1河川・1公式仮定シナリオ。ソースが受入前なら明確な合成データ/モックを使い**実際の行政予測として見せない**。APIの高頻度呼出しや本番利用は許可しない。
- T-2 静的表示：権利/取得範囲/原本/ハッシュが検証された公開可能な時系列データを事前加工して静的配信、又は許諾された公開タイルをブラウザから参照する方式を比較。リクエスト数とキャッシュの制約を測定。
- T-3 実データでの限定公開：A/C独立原本確認、出典/想定条件/版、利用規約、失敗時UI、PC/スマホ操作、公開判断のゲートをすべて満たした対象に限る。未受入ならT-1のプロトタイプに留める。

## ステータスや失敗時の要件

- 非対応の河川/地域、選択できる破堤点なし、想定条件不一致、時間データ無し、API障害/レート制限、ユーザーがGPSを拒否、通信断、表示時刻と取得結果がずれるケースは、推測値で補完しない。
- 想定最大規模の静的洪水浸水想定と、破堤点別の時系列シミュレーションを同じシナリオ・時点と見なさない。異なる版/条件の重ね合わせには独立検証が必要。
- 「浸水が到達するまで〇分だから逃げられる」「この施設が安全」「この経路なら通れる」等を自動表示しない。
- APIキー等が将来必要になっても静的配信のJS/公開HTMLへ秘密情報を埋め込まない。
