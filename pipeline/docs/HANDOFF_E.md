# E担当への引き渡し — GIS / Map

EはDが正規化した位置情報を地図表現へ利用します。

## 現在利用できる主なフィールド

`shelter_location` の各record:

- `id`
- `name`
- `latitude`
- `longitude`
- `address`
- `administrative_area`
- `facility_type`
- `detail_url`

## 座標の扱い

- `latitude` / `longitude` は`null`になり得ます。
- Dは住所から暗黙にジオコーディングしません。
- 座標がないrecordを地図から黙って消す場合は、UI上で件数差が分かるようにしてください。
- 将来ジオコーディングする場合、公式座標と推定座標を区別できるEvidence/品質属性を追加してから利用します。

## 名古屋市の現行Dataset scope

- 現行D Adapterは公式ページの16区別**屋内施設Excelのみ**を取得・正規化する。
- 同ページ上の屋外施設データは現行 `shelter_location` Datasetに含めていない。
- 1602件などのrecord件数を、名古屋市公式ページ上の全避難関連施設数として扱わない。
- 屋内Datasetに機械可読な緯度経度がないため、現在のD出力では座標を推測せず `null` のまま保持する。

## 責務分離

- D: 取得・正規化・品質判定
- E: 地図描画・レイヤ・空間可視化

E側で自治体固有CSVを直接解釈しないことを推奨します。

## 洪水Scenarioの任意地図表示

`RegionExport.scenarios[]` の `facility_results[].fact.latitude/longitude` がある場合のみ点表示してください。座標を推測しないこと。`洪水・内水` 等のraw事実をEで洪水単独の判定へ変換しません。ラスタ色と施設点を交差して独自の安全判定を生成することも禁止です。

**新潟市の洪水CSVの階数条件**: `fact.usable_floor_raw` は `2階以上` / `3階以上` / `全階可` の公式raw表記を保持するための任意項目です。該当施設の `UNKNOWN` を、位置座標があっても `CANDIDATE` へ昇格させないでください。座標付き `UNKNOWN` 件数・原文・Sourceを説明可能に保ち、階数情報から避難ルート安全性や開設状況を推測しないでください。


### 新潟ODSの公式記号に関する保留（Issue #48）

Dの保守的更新後、現行新潟CSVの全施設が `UNKNOWN` です。元データの `○`/`×` をEで候補点/除外点に変換してはいけません。座標付き `UNKNOWN` は地図上で不確定な公式事実として表示できますが、危険度、開設状況、ルート安全性や公式推薦を示唆するアイコン・色分けに使わないでください。GISの位置可視化と適合判定を分離してください。
