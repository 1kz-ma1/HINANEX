## 1. 境界と安全ゲート

1. **Stage 8**: ABR候補参照点とGSI登録参照点を航空写真に重ねた**人間の目視所見**を収集・記録する。敷地境界・建物・入口の法的または公式な位置確定ではない。
2. **Stage 9**: 各候補位置を**施設を特定する独立の公的資料等**と照合し、根拠を残して**別担当者による確認・責任者の位置受入判断**まで進める。AIは調査順序、証拠整理、矛盾検出を支援するのみで、座標の選定・位置受入を代行しない。
3. **GIS/RegionExportへの昇格**: Stage 9で位置の受入候補になっても**別ゲート**。後方互換の品質・provenance契約、依存Consumer、テスト、公開許可、Merge Captain審査が必要。
4. **災害への適合性・施設指定区分・開設可否・経路安全性**: 位置証拠とは別軸。位置が分かっても安全な避難先と表示しない。

全9件の現行フラグを保持する:

- `approved_for_map=false`
- `data_promotion_authorized=false`
- `official_facility_positions_accepted=0`
- `site_position_independently_verified=false`（現時点で独立確認完了の根拠なし）

現在の`hinanex.team-review.v1`は**名称・住所・出典の班員レビュー用**であり、位置承認の契約ではない。手動・自動を問わず承認フラグを変更しない。`status=needs_follow_up`と位置受入保留の意味を維持する。

## 3. Stage 9 — 人間主導の独立位置検証

### 3.1 実施条件と役割

- **調査担当（人間）**: ローカルのPRIVATE台帳を権限のある端末で開き、公開の根拠資料を人間が確認し、個別記録に転記する。候補点を平均・補完・自動選択しない。
- **AI**: 検索語・手順の案内、論点の説明、報告文の整形、不備チェック。PRIVATE CSV・生の座標・施設別の比較画像を外部AIサービスへ投入しない。
- **独立レビュアー（人間）**: 同じ担当者の自己確認に依存せず、原資料を自ら開いて判断の再現性・反証可能性を確認する。
- **受入責任者（人間）**: 施設位置について個別に承認／保留／不採用を判断し、根拠と日付・判断者を閉域の記録に残す。AIが代理承認しない。
- **統合担当（Merge Captain）**: 後日のコード・Contract・データ統合を別途審査する。位置受入とmerge許可は異なる。

### 3.2 照合の順序

1. **第1群：重複ABR参照点の2施設**
   - 元住所と施設同一性を再確認し、ABRの`match_level`と`coordinates_level`、応答の版・根拠・共通代表点の可能性をローカルで検査。
   - 同一点になった原因が明らかでなくても、座標を自動採用・訂正しない。GSI登録点と別途公的な位置証拠を比較する。
2. **第2群：その他のABR敷地外目視4施設**
   - ABR候補点が示す対象、GSI点が示す対象、施設配置図・校舎案内・敷地図等との整合を調査。
   - **入口付近に見える**ケースでも、正式な入口と断定しない。
3. **第3群：ABR敷地内目視3施設**
   - 敷地内に見えることを理由に省略しない。施設同一性、建物／敷地／入口のどれを点が代表するかを別資料で検証する。
4. **横断：GSI参照点9件の独立照合**
   - GSIが自治体登録点に由来する可能性や資料の循環参照を考慮し、**GSI一致だけを独立測位証拠としない**。
   - 画像の撮影時期、登録時期、対象の移転・改修・施設名称変更の有無を確認。日付の不明な資料は不明のまま残す。
5. **別担当者の再確認と責任者判定**
   - 施設ごとの資料を別の担当者が再確認し、責任者に位置受入の判断材料を渡す。矛盾・未確認が残れば**HOLD**。

### 3.3 個別施設で確認する証拠（PRIVATE側のみ保存）

- 元の施設IDと元データfingerprintが**同一**であること（元データと照合して再計算、相違は停止）。
- 名称、住所、施設種別（原資料にある限り）、建物・敷地・入口の対象の区別。
- **出典のURL、発行主体、文書名、版、公開／更新／撮影年月**（分からなければ`UNKNOWN`）。
- ABRとGSIの位置参照点に対応する施設同一性、点の意味、ズレ・競合・代表点の有無。
- 住所参照点と施設位置の対応を裏付ける**独立した公的資料**（例: 施設配置図、管理主体の位置図、施設案内の住所・建物識別情報）。同じ出所をコピーした複数地図は独立根拠と数えない。
- 目視記録・公式資料で一致する点、相違する点、解決不能な点とその理由。
- 担当者の所見と確認日、独立レビュアーの所見と確認日、責任者の判断と日時。
- 施設別の詳細、座標、スクリーンショット、候補地図リンク等は**承認されたローカル台帳のみ**で扱う。共有用テキストには必要最小限の公開根拠URLと結果分類のみを書く。

航空写真は補助証拠であり、**敷地境界の確定や入口位置の証明を単独で満たさない**。十分な証拠が得られない場合、架空の座標や「おそらく正しい」という結論を補わない。

### 3.4 受入判定と停止条件

これは**作業記録上の分類案**であり、既存JSON SchemaのstatusやGIS契約へ新しいenumを勝手に追加しない。

| ローカルの検討区分 | 意味 | 次の処理 |
| --- | --- | --- |
| `READY_FOR_INDEPENDENT_REVIEW` | 出典・位置の意味・比較の根拠が揃い、別担当者が検証できる | 人間の独立レビューへ |
| `NEEDS_MORE_EVIDENCE` | 資料・版・位置の意味が不足 | 保留、追加の公的資料を探す |
| `CONFLICT_OR_UNRESOLVED` | 根拠が矛盾／別施設・代表点の疑い／判定不能 | 保留、責任者へ報告 |
| `HUMAN_POSITION_ACCEPTED` | 別担当者の再確認を経て、**権限ある責任者が位置用途・根拠を限定し明示受入** | 非公開承認記録を維持。GIS反映はなお不可 |

以下のいずれかがあれば、位置受入を止める: 施設同一性が曖昧、資料の更新・撮影時期が不明で位置変更の可能性を排除できない、参照点と実施設の意味が混同、資料間で矛盾、出典の独立性を説明できない、責任者・再確認者の判断証跡がない。

**現時点の件数は常に`HUMAN_POSITION_ACCEPTED=0`と報告する。** この文書の追加はその件数を変更しない。

## 4. HTMLツールを使わない報告フロー

現行の班員向け`hinanex.team-review.v1`は名称・住所等の確認結果として既に受領しているため、Stage 9担当者にHTMLで再読込・再出力を求めない。

1. PRIVATE台帳は、アクセスが許可された端末でのみ確認。個別の照合証跡はローカルで管理する。
2. 調査担当は以下の**テキスト／Markdown形式**で追加確認結果を受入責任者へ送る。生緯度経度・PRIVATE台帳・座標付き画像は送らない。
3. 受領者は対象ID／資料URL／日時／前回の所見との矛盾を確認し、必要な追跡情報をローカル台帳へ反映する。記録形式は未承認の公開JSON Schemaに混ぜない。
4. 責任者が位置受入を行う場合は**別途承認記録**に署名・保存する。現行の安全フラグやRegionExportをこの報告だけで更新しない。
