# HINANEX — E / GIS

`gis/` は E担当（GIS / Map / 空間可視化）の領域です。

実装入口は `gis/` サブディレクトリです。

- UI / 起動方法: `gis/README.md`
- E仕様: `E_GIS_SPEC.md`
- テスト: `tests/`

Dの `RegionExport` をconsumerとして利用し、自治体固有Rawデータの解釈や暗黙geocodingは行いません。

## 洪水Scenarioの公式raw Evidence（任意Consumer）

Dの`RegionExport.scenarios[]`に`scenario_id=flood_shelter_selection`がある場合、既存の`shelter_location.records[].id`と**完全一致**で結合して、マーカー詳細に以下を表示します。

- DのScenario status（再判定しない）
- 災害列名のraw、施設単位の公式raw値（`○`/`×`/`－`など）
- `usable_floor_raw`（`2階以上`などの階数条件の原文）
- 元の施設行・source URL・Dの理由
- 地域の情報パネルに、Scenario UNKNOWN件数と公式rawの取得状態

**重要**: 地図の施設点はあくまでDの座標付き`shelter_location`レコードです。Scenarioの`UNKNOWN`を候補外と解釈したり、記号や公的洪水ラスタとの位置重ね合わせから独自に洪水時の利用可否・建物安全性・ルート安全性を判定したりしません。座標のない施設は従来どおり件数へ残し、推測補完はしません。

旧RegionExport（Scenario未搭載）はそのまま表示します。Scenario施設IDが位置レコードと一致しない場合は安全のため読込失敗とし、曖昧な施設名マッチをしません。出典URLは既存`safeExternalUrl()`を通して無効なスキームを拒否します。

**Gitと統合について**: 現在の`role/e-gis`はmainに対し大幅に遅れていたため、今回は最新mainから`feature/e-flood-scenario-evidence`を作成し、E担当`gis/**`だけを変更します。D #46がmain未統合の間、このconsumer PRは依存ありのDraftとし、Merge Captain判断を待ちます。

## 2026-10-08 地図の無座標表示・ブラウザ警告

- Nagoya公式raw資料の1,602施設には機械可読な緯度経度がないため、`records=1602 / 地図表示=0 / 座標欠損=1602` は正常なデータ状態です。位置を推測して表示しません。
- 地域切替で前の地域の地図が透けて誤認されないよう、座標と参照境界のない地域は**不透明な未確定オーバーレイ**で地図本体を覆います。対応する公式座標を取得するまで地図位置は確定しません。
- 既存`supported_disasters`は`元データ記載の災害（適合性未検証）`と表示し、Source上の文字列と洪水Scenarioの独立した`UNKNOWN`を混同しません。
- Microsoft Edgeの`Tracking Prevention blocked access to storage for https://unpkg.com/leaflet@1.9.4/dist/leaflet.css`は、第三者CDNに対するブラウザストレージ制限の警告です。**地図ライブラリが正しく読み込めないことをこのログだけから断定しません**。もしLeafletのCSS/JSが実際にブロックされた場合は、別途ロード成否を確認して静的アセット配布の方針を決めてください。これは無座標や洪水Scenarioの判定とは独立です。

## 無座標施設の検索・閲覧モード（E / GIS Consumer）

Dの `shelter_location.records[]` が存在する一方で **座標付きレコードが0件** の場合、Eは推測地図を描く代わりに一覧モードへ自動切替します。例：名古屋市の2026-10-08時点の屋内施設データ1,602件（公式raw照合済み、座標表示0件）。

- 名称・住所・行政区域・施設ID・Scenarioの公式raw値や利用階原文で検索（全角/半角や空白を検索時のみ正規化）
- 1ページ20件のページ送り。ヒット0件も明示。**元recordsは全件保持**し、元の文字列は変更しない
- `details/summary` で各施設の住所・行政区域・種別・Dに記載された災害種別・元のScenario status・公式raw値・利用階原文・照合方式・元Source行・判定理由を表示。SourceリンクはHTTPSに限り表示
- 洪水Scenario自体が未搭載の旧RegionExport 0.9でも一覧は利用可能。公式raw情報が存在しないときに適合性を埋めたり推測しない
- 名古屋市での洪水・内水は混合列で、HINANEX独自に洪水単独判定へ分割しない。UNKNOWNは危険・利用不可・開設なしを意味しない
- モバイルでも詳細は一覧内展開可能（右サイドパネルを前提としない）
- 座標が確認できる地域では従来の地図/マーカー機能を使い、切替時は古い検索語や前地域の一覧をクリアする

**DのSchemaや施設のSource/座標は変更しません。** 明示的geocoding、AIの施設候補選定、避難経路の安全計算、現在の開設案内は実装しません。

実装：`gis/gis/js/facility_list.js`（検索/ページングのみ）・`gis/gis/js/map.js`（UI接続）。回帰テストは `gis/tests/facility_list.test.js` と `gis/tests/map_controller.test.js`。

## 10/22 MVP: 現在地 × 洪水公式指定緊急避難場所（参考探索）

江戸川区のGISで、ユーザーは **地図上の地点を手動クリック**するか、**位置情報を明示的に許可した場合のみ**現在地を選択できる。位置の座標はブラウザ内で保持し、位置座標をHTTPリクエストに付加しない。

別データとしてDが発行した C-accepted GSI洪水指定緊急避難場所カタログ `pipeline/data/output/edogawa_flood_site_catalog.json` を、地点を選択して初めて読み込む。カタログの `REFERENCE_ONLY + C_ACCEPTED`、公式タイルSource、施設の元名・住所・備考・座標・Source hash/feature traceを確認できた時だけ**直線距離の近い5地点を参考掲載**する。距離が近い=安全、行くべき避難先、経路時間、実際の開設中ではない。江戸川区公式の広域避難方針へのリンクを常設。

カタログ不存在、C未承認、内容異常、GPS拒否・未対応時は明示的な説明を表示して安全に終了。既存 `shelter_location` 152件、3地域の `UNKNOWN` Scenario、国土地理院の浸水想定参照ラスタなどから適合性を推測しない。名古屋の無座標施設一覧モードも既存どおり保持する。

**手順**：
1. A公式ソース調査 → D archived GSI skhb01 Source normalize → C独立raw監査 → D参考カタログ生成。未認証データでは掲載は0件。
2. HTTP配信で `/gis/gis/?region=13123` を開く。
3. 「地図から出発地点を指定」を押して地図をクリック。端末のGPSは別ボタンで明示許可を要求。
4. 一致した公式掲載地点がある場合のみ、公式住所/Source/直線距離を確認。江戸川の広域避難指針を優先。

**テスト（Node）**：
```powershell
node gis/tests/flood_discovery.test.js
node gis/tests/map_controller.test.js
node gis/tests/facility_list.test.js
node gis/tests/d_region_adapter.test.js
node gis/tests/region_exports.integration.test.js
```

公式の配布GeoJSONに対するA/C実検証が完了するまで、GSI Sourceの`REFERENCE_ONLY`掲載を正式な自治体データ検証PASSとは扱わない。

## 2026-10-09 日本列島が収まる縮小限界（Map-first v4）

- GISのLeaflet地図で、画面サイズに応じて**これ以上縮小できない最小Zoom**を設定する。固定の数値だけで決めず、`map.getBoundsZoom()` で日本列島の概略表示範囲が収まる倍率を計算し、`map.setMinZoom()` でホイール・ピンチ・拡大縮小ボタンに共通適用する。
- 概略範囲は南西諸島～北海道の `[[24.0,122.5],[45.8,146.5]]`。これは**画面操作の目安**であり、日本の行政界・災害リスク域・全離島の網羅・公式データのカバー範囲を意味しない。極東の離島や一部遠隔島嶼は対象外。
- 画面回転・リサイズ時は再計算。ズーム変更を強制する必要がない状態なら地図の中心/選択地域/施設/出典/シナリオを初期化せず、広域拡大・詳細確認には制限を設けない。
- 使用可能な地理院背景タイルのminZoomを2へ下げ、広域ズームでも意図しない背景欠落が起きないようにする。公式洪水ラスタも同じ2以上の範囲だけを要求するが、低ズームでの未取得を「浸水なし」とみなさない。
- Zoom最小値は計算結果を地図タイル下限2～大型画面の上限6でclampする。GIS Eレイヤーのみの表示改善。防災評価やデータの座標・公的意味・操作モード・GPS権限は変更しない。
- Eの独立回帰テストで初期設定、レスポンシブな再計算、操作状態維持、旧CIのasset cache一致を確認。モバイル/PC各実機の実際の表示領域・Leafletタイル取得可否は別途確認する。

## 2026-10-09 地図パン・ズームの第1段階パフォーマンス改善

- Leafletの地理院背景地図と公式洪水ラスタ双方に `keepBuffer:3` を指定し、短いパン操作で既存タイルの保持量を少し増やす。 `updateWhenZooming:false` によりズームアニメーション途中での不要な新倍率タイル要求を抑え、最終倍率で読み込む。移動中に旧タイルを一時的に拡大する場合はあるが、透明・欠落を「浸水なし」と解釈しない（既存の未取得警告は維持）。
- `renderDMarkers()` の `clearLayers()` 毎回全削除を廃止。表示範囲のDレコード行index集合をキーにして、**クラスタの構成が同じ場合は同一Leafletマーカーを再利用**し、変わったものだけ追加・削除。RegionExportの再読込／地域切替時にはキャッシュを必ず破棄する。元座標・件数・UNKNOWN・公式raw意味・表示集合の重心位置・クリック内容は変えない。
- `?debugMapPerf=1` を付けてブラウザ開発者コンソールを開くと、背景タイル／公的洪水ラスタの読み込みバッチ完了時間、およびD表示マーカーの追加・削除数・処理時間を確認可能。デフォルトでは計測イベントを登録しない。座標や個人のGPS位置をログに出さず、通信先にも送信しない。
- 日本列島を基準にする縮小限界のロジックは**そのまま**、ズーム倍率の刻み（`zoomSnap`）の変更は実機比較まで見送り。
- E回帰テストで tileオプション、同一クラスタ・個別マーカーの再利用、元座標・参照データ維持、過去の描画回帰を検証。CIだけでは体感FPSや外部GSIホストの待ち時間は保証できないため、PC／スマホ実機の比較が必要。

## 2026-10-09 Zoom gesture tuning（第2段階）

- 地図操作は Leaflet `zoomSnap:0.5` / `zoomDelta:0.5` / `wheelPxPerZoomLevel:100`。ホイールと拡大縮小ボタンが急に1段飛ぶ動作を緩和する。Leaflet標準アニメーション、地図の中心、現在地許可、日本列島を基準にしたレスポンシブな最小ズームは維持。

- 現行3地域の座標付き施設のみが表示候補。名古屋の無座標レコードは地図上に配置せず一覧へ案内。複数地域をまたぐビューや広域ズームでもソースと元の件数・UNKNOWNを保つ。
- Leafletのmoveend/zoomendで判定し、短い遅延と前回範囲・読込済みセットの比較で不要なHTTP/再描画を抑制。旧リクエストは既存AbortControllerの考え方で安全に取消。パン中のfitBoundsは行わない。
- GSIの指定緊急避難場所探索は現在のC-accepted範囲・地点選択要件を維持し、D施設・公式洪水ラスタと明確に分離。地図タイル未取得は『浸水なし』を意味しない。データがない領域は『未確認・未対応』と明示。
- 実装前にカバレッジの出典・3地域境界の信頼度・広域ビューの仕様・失敗時挙動・表示モードとの関係を検証し、D/C契約の追加が必要なら担当ごとにPRを分ける。

## 2026-10-09 操作遅延への修正（連続ズーム・応答性優先）

- ユーザー実機フィードバック：`zoomSnap:0.25` / `wheelPxPerZoomLevel:240` は逆に縮尺変更が遅すぎた。ホイール入力の反応と視覚上のカクつきを別問題として扱う。
- **通常モード**では `zoomSnap:0`（Leaflet標準の無段階スナップ解除）／`zoomDelta:0.5`（＋・－・キーボードの確定操作）／`wheelPxPerZoomLevel:100`／`wheelDebounceTime:40`。整数や0.25刻みへの吸着をなくし、反応速度は前の値へ戻す。Leaflet標準地図アニメーションは変更しない。
- **タイル**：地理院背景地図の `updateWhenZooming:false` に戻してアニメーション中の差し替え描画と追加要求を抑制。公的洪水ラスタも従来通り `false`、双方 `keepBuffer:3`。表示欠落は安全・浸水なしの意味ではなく、従来の警告を維持。
- 旧挙動比較：`?zoomFeel=previous` = 半段スナップ／100pxホイール／背景更新false、`?zoomFeel=slow` = 0.25段／240pxホイール／背景更新true。新規導入するパラメータは地図操作のA/Bだけに適用し、GPSや元データ、表示自治体には影響しない。
- `?debugMapPerf=1` で既存のタイルバッチ・Dマーカー処理時間に加え、ズーム開始〜終了の時間と最終ズームをブラウザコンソールへ出力（緯度経度・GPS・利用者識別子なし、外部送信なし）。有効化しない限り計測しない。
- 日本列島を基準にした最小ズーム・既存施設データと正本・GSI/洪水ラスタの独立性を維持。GIS回帰テストは通常／2比較モードのズーム設定・背景タイル・実装バージョン識別子を検証。CIは操作感の実測ではないため、PC/モバイル実機で比較する。

## 2026-10-09 地図操作のユーザー設定（Map gesture preferences）

- 下部ナビの既存「設定」を地図の操作設定として利用できるようにする。設定シートは他メニュー・施設詳細と排他的で、外側タップ/Esc/×で閉じる。「やること」「マイ情報」は引き続き予定表示。
- ホイール・タッチパッドの感度を **0.5～2.5倍**、0.25刻みで即時変更。初期値1.5倍（約67px/zoom）は以前の100px/zoomより速い反応。ピンチ操作にはこの感度設定を適用しない。
- ズーム方式は「連続（zoomSnap=0）」「段階的（zoomSnap=0.5）」から選択。＋／－とキーボードの zoomDelta=0.5 は維持。これはLeaflet標準操作でありGoogle Maps同等の完全ピクセル追従を保証するものではない。
- window.HINANEX_MAP_GESTURESの限定APIで map.options.wheelPxPerZoomLevel と zoomSnap を更新。地図の現在地・ズーム・RegionExport・GSI/洪水公式データは再取得・移動しない。
- 設定は同一ブラウザlocalStorageの hinanex.gis.gesture.v1 に感度・方式だけ保存。ブラウザで保存を拒否された場合もそのセッションで使える。位置・GPS・施設情報・災害情報・ユーザー識別子は保存しない。
- 従来の比較用 ?zoomFeel=previous|slow は初期挙動として引き続き有効。設定を変更したらその場で設定が優先される。
- E回帰テストは初期値、即時反映、再訪時復元、無効値補正、保存拒否、設定シートの排他的な開閉、地図のズーム限界・位置保持を確認。操作感はPCマウス/タッチパッド/スマホで実機チェックが必要。

## 2026-10-09 小刻みズーム時のDクラスタ安定化

- 実機動画では広域ズームで地図タイルが一時的に粗くなる場面があり、ラスター画像自体の拡縮・取得の制約は感度調整だけでは解決できない（FPSや通信時間は未計測）。
- 画面表示用Dクラスタはズーム13未満では整数バンドを使用。同じバンド内の小数ズーム変更では再投影・再クラスタをスキップし、境界を越えたときだけ更新。**地図の倍率そのものは無段階のまま**。
