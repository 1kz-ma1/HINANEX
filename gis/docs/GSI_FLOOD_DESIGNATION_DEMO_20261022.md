# GSI洪水公式指定の発表デモ（2026-10-22、E担当）
GISの「場面 → 発表用ガイド付きデモ → 50秒：洪水の指定がある場所を公式データで確認」を本編にする。従来のD名称絞り込み52秒版とCの2019年検証は補助として残す。

国土地理院の資料 https://maps.gsi.go.jp/help/use.html はGSI GeoJSONの skhb01 を洪水と定義し、disaster1=1 をその災害に対応する指定の意味と明記する。利用上の注意 https://www.gsi.go.jp/bousaichiri/hinanbasho-menseki.html に従う。

0-7秒：現在のD施設とGSI公式指定データは別情報源であると示す。
7-19秒：既存C/HTTPS検証済みのGSI skhb01レイヤーへ切替。GSI自体が洪水用に抽出された公式掲載情報であり、「D全施設から安全を選別した」のではない。
19-31秒：本物のGSI掲載地点へ移動し、元の名前、住所、disaster1=1、feature_index、元タイルへの公式リンクを表示。
31-43秒：GSIとD施設を別レイヤーで表示し、D側の洪水UNKNOWN件数を別に示す。施設同士の同定・承認は行わない。
43-50秒：現在は指定を出典まで追える。開設・災害現況・安全な経路との結合は将来構想。

GSI取得は既存のHINANEX_FLOOD_DISCOVERYのC_ACCEPTED/HTTPS一致/源SHA/出典GeoJSONタイル/feature_index/disaster1_raw=1検証からのみ。未検証タイルや選択位置が範囲外ならfail-closed。検証済みのタイル内の掲載件数と自治体全域の指定施設数を混同しない。DのUNKNOWNを危険・非掲載へ変換しない。元の視点と閲覧状態は閉じる時に戻し、ユーザーが地図を操作した際には位置を優先する。

GitHub CIではレイヤー切替、原文の照合、D非join、情報源の検証失敗、50秒の時間配分、中断と復旧を検証。Render/Edge/モバイル画面と7分リハーサル、配布済み検証タイルの実在は別途実機で受入する。
