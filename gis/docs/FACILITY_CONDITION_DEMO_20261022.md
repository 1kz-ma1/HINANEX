# HINANEX 発表：実D施設の条件絞り込み・根拠照合（2026-10-22）
本編入口：GIS /gis/gis/ → 場面 → 発表用ガイド付きデモ → **52秒：施設を条件で絞り込んで確認する**。旧55秒・90秒の2019年検証演出は補足用に残す。2019年の事後資料を現行GIS施設に紐付けない。

## 再生工程
0–8秒：現在選択中の地域の本物のD RegionExportから総件数、元座標あり、座標未確認数を取得、地図を実座標範囲へ移動。
8–20秒：実データの施設属性で部分集合を作り、GISの実マーカーを絞り込む。件数はDに基づいて動的に表示。
20–34秒：該当レコードの元座標へ移動して名称を示す。
34–45秒：抽出条件・施設のD原値・洪水対応分類・元の照合理由や出典（存在する場合）を比較。
45–52秒：今できること「属性での絞り込みと出典確認」と将来の「災害条件を用いた避難先選定支援」を明確に分離して伝える。

## 属性選択の真実性
現在のD Scenarioは多くがUNKNOWNであり、洪水適合施設を絞る機能が完成したと宣伝できない。CANDIDATE・EXCLUDED両方が存在する「分類済み」は安全判定ではない。最初に分類済みとUNKNOWNが混在するかを調べ、ある場合だけ分類済みという属性で抽出する。なければ、レコード名に「小学校」「中学校」などの**文字列を含む**という検証可能な条件で抽出し、次にfacility_type/administrative_areaの元値を使う。D属性で真の部分集合が作れない場合、嘘の件数を出さずに停止。

**名称の一致は、洪水で安全・開設している・避難先として適切、という意味ではない。** 当日の開設・混雑・浸水・避難経路は評価しない。Eは新たな座標や公式データを推測しない。別系統のGSI出典と混合しない。

## データ・UI・復帰
HINANEX_D_ADAPTER出力と既存`dRecordVisible`の実マーカー生成ルートに、発表時だけ選択レコードID集合制限を追加。戻る際に表示モード・元のフィルタ・D表示・地図視点を元に戻す。手動地図操作ならその視点を保存。DのSchema/公式raw/分類値は変更しない。
