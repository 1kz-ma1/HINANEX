# HINANEX MAIN AUDIENCE DEMO — 江戸川区の2施設比較へ転換（2026-10-21）

## 決定
以前の検討で、周辺にある千葉県側のGSI紫ピンをメインで紹介するより、**江戸川区として収録した施設同士を地図上で比較する**デモを優先する方針を採用した。2026-10-21のユーザー確認を受けて、QR/共有入口のメイン動線をこの体験へ差し替える。

- 旧GSI洪水指定/掲載地点の独立検証機能、公式出典リンク、GSI/Dの区別は保持する。ただし旧GSIの4場面自動説明は「比較を始める」通常動線から外す。
- 既存D RegionExport `region.code=13123` `shelter_location` の `mappableRecords` を唯一の比較対象とする。最新データで正しく取得できる場合にだけ画面に一覧を出す。架空の施設、GeoJSON、住所補完、GSI/Dの住所による自動結合は禁止。
- 比較対象は取得データ上の施設であり「現時点で江戸川区が正式に開設している避難所」ではない。記録の地域コードに基づく表示は行政界内の全座標検証も意味しない。
- 本人がセレクトメニューで**異なる2つ**を選び、名称/住所/種別/区域/収容人数/元座標の存在/洪水Scenarioの状態・理由・Source URLを並べて見る。値なしを事実上の0・安全・閉鎖に読み替えない。文字は `textContent` で描画。
- 「2件を地図で見る」の**ユーザー操作時だけ**2つの元座標に `fitBounds`。GSI/千葉県側へ強制ズームしない。
- 比較中のA/B markerは元のD座標からのみ生成し、避難推奨順位を意味しない。
- 江戸川区は広域避難を原則とし、待避施設はやむを得ない際の緊急避難先という公式説明を併記。二つの資料間の自動施設同一性判定はしない。

## 既知の境界と自動停止
- D施設の洪水分類は `UNKNOWN` の場合そのまま表示。 `CANDIDATE` もそのまま安全認証にはしない。
- 取得できない、レコードが2件未満、両者同じID、地域が切替、未承認GSI資料を使う場合は比較不可。
- 生の地域施設レコードに記録された出典URLがある場合のみ安全なHTTPSリンクで表示。ソースがない場合はリンクを作らず「元データで未確認」。
- 未検証情報を条件にした推薦・ソート・自動経路、安全確定は行わない。
- 新旧プレゼンターは同時に実行しないことが望ましく、メイン共有CTAでは旧GSIを起動しない。既存のGSI presenterは従来機能として維持。

## 実行/受入
- `?demo=audience` のWelcome →「デモ開始」で江戸川区施設比較が起動。本人操作なしの自動GPS・自動再生なし。
- 1365px PC / 390pxモバイルのChromiumで、施設2件選択、属性・UNKNOWN比較、2件のみの地図移動、閉じる操作を確認する。
- 旧GSIソース検証のChromium経路は開発専用の明示起動で回帰確認する。Web上のGSI原本配信や正式A/C承認を証明するものではない。
- 実機Safariと聴衆への説明の分かりやすさは別途レビュー。

## 開発統合
- 変更はEの `gis/**` に限定。新しいPublic Contractは作らず既存のD adapterを使う。
- 最新mainと必須CI、E専用実ブラウザ受入が成功するまでmainへの統合はしない。


## 2026-10-21 実録画からのAudience UX受入修正（新しい小規模PR）

約41秒のPC操作動画（1920×886収録）で、操作自体は可能だが発表内容の伝わり方が弱いことを確認した。

**動画で観察した問題**
- 江戸川区周辺の黄色い施設ピン・集約ピンが多く、選んだA/Bマーカーより目立つ。
- 比較に入っても2つの選択メニューと操作ボタンが右側に残り、肝心の比較表の見出しが画面下に押し出される。
- 比較した結論が「何が分からないか」と紐づかず、施設A/Bの長い属性表の羅列で終わる。
- スクロールしないと出典や理由が見えないが、短い発表では全項目を見せる必要はない。

**今回の実装変更（表示のみ）**
- 開始時の問いを「地図にある施設だけで、避難先は決められる？」に統一。最初から選択2行を見せず、次の操作時だけ施設A/B選択を表示。
- 比較完了時は選択UIを閉じ、同じパネルの最上部に「両方UNKNOWN＝安全でも危険でもなく未判定」を明示（片方でもUNKNOWN以外の元値なら別の一般的な注意）。これはD原値の再判定・補完ではない。
- A/Bカードは施設名、住所、施設区分、洪水の記録状態のみ主表示。収容人数・ID・原判定理由・記録済みHTTPS出典は各カードの「その他の元データ・判定理由」を開いた時だけ表示。公式の広域避難・待避施設説明と注意事項はパネル下部の「公式方針・出典と比較上の注意」に保持。
- 比較中、地図のD既存ピン（shelter pane）を**CSS opacity 0.12**に下げ、出典の事実・取得件数・クリック元データ自体は一切変更しない。A/Bは独立したパンにより元座標でくっきり表示。デモ終了後は自動的に従来の視認性へ戻す。
- 「A・Bの位置を確認」「別の2施設を比較」を結論の直下に配置。利用者が押した時だけ地図を移動し、閉じると元のビューと表示モードへ復帰する。
- PC版結果パネル上限 43dvh / 385px、スマホ44dvh。背景地図を覆う面積を抑えるが、情報自体はスクロール/展開で確認可能。

**検証ゲート**
- required \`test\` のE controllerと独立したChomium受入：導入1場面では選択肢を見せない、2件を選ぶとA/B表示、比較時は選択を収納して主要データと未判定の結論を先頭へ、背景D群の減光、実際のクリックによる2地点camera focus、PCのパネル寸法、モバイルの地図占有を自動検査。
- 実機ブラウザ、発表時の説明速度・色弱者の認知は別途確認。**安全な避難先と示したものではなく、各D施設情報の比較可能性／未判定の境界**を伝える教育的デモ。


## 2026-10-21 UX追加：お任せ選択とWelcomeの開始ボタン固定

実際の発表画面（PC）のスクリーンショットで、長いWelcomeの説明の下に開始ボタンが隠れ、意図せず「×」を押して案内を閉じるリスクが確認された。データ比較にも参加者が選べる簡易ルートが必要になった。

**Welcome:** 見出し＋独立した説明スクロール領域＋独立した固定CTAフッターに再構成。説明をスクロールしても「▶ デモを開始する」は移動せず、×を押すか開始を押すまで案内は閉じない。PC/390pxとも、カードの底辺より上にCTAが見えることをChromium受入で確認する。狭い画面では説明文だけをスクロールできる。公式区の方針・文言・リンクは削除しない。

**2施設のお任せ:** あくまで同一RegionExportの江戸川区 shelter_location に紐づく、**既に座標を持つ実レコード**から選ぶ。モデル内部の既存 records を名前順で受け取り、施設区分（D原値）が存在する先頭1件を起点に、異なる区分があればその先頭1件を優先。そうしたペアが取れなければ先頭2件を選ぶ。ランダム／GPS／危険度／浸水／距離／収容人数／現在の開設／出典信頼度の順位付けは使わない。

「お任せで2件を比較」は表示されている実レコードから2つのKeyを選ぶUIのみであり、既存 api.compare と全く同じ出典保持ロジックに進む。施設が2件未満、begin失敗、キー重複ならボタン無効・従来のfail-closedを維持。手動選択も従来どおり可能で、選択画面から再度お任せできる。結果画面には「デモ用自動選択・安全性/距離による推薦ではない」と明示。Dの元施設区分 facility_type を、E内の既存比較UI APIが返す一覧に読み取り専用で追加（既存キーは変更しない）。

**受入条件:** デスクトップと390pxスマホのreal Chromiumで、説明欄を最後までスクロールした後も開始ボタンがカード内に残り、カードが勝手に閉じない。お任せと手動の両方で実レコード2件に紐づくA/B表示、同一キー拒否、デモ選択根拠の表示、従来のUNKNOWNと出典を損なわない。実機Safariの人間受入は別途。


## 2026-10-21 Mobile viewport correction — staged, map-led evidence

ユーザーの実機スクリーンショットでは、約300px幅のスマホ地図に対して2施設の情報カードが縦方向に重なり、地図の閲覧領域が小さくなっていた。今回の改訂で「比較結果を大きな2カードで一度に表示」する構成を廃止し、手動選択またはお任せでの **1回の明示操作**を起点に次の流れへ変更する。

- **Aを見る:** 既存D RegionExportのA施設元座標にマップをズームし、Aの施設名・住所・記録された施設区分・元の洪水分類だけ表示。収容人数・ID・元判定理由・出典は施設カード内の手動展開で確認。
- **Bを見る:** 「次：Bを見る」またはBタブ／地図マーカークリックで、同じ処理を実データのB座標に適用し、表示する詳細カードもBへ入れ替える。
- **比較の結論:** 2地点が見える範囲へ遷移し、両者の名称・区分と、元データから分かること／洪水時の利用可否は未判定という結論だけを短く表示。再度A/Bへ戻ることも可能。
- A/Bは常に既存のD地点のマーカーを使い、選択中の片方だけCSSで強調。他のD地点はデモ中だけ従来どおり減光。GPS、住所ジオコーディング、避難推奨、ルート推定、GSI/D同一地点結合なし。
- モバイルの **結果パネル最大29dvh/213px**（内容の詳細はパネル内スクロール）。先頭の3ステージボタンは固定し、パネルが大きくなっても地図領域を維持。選択中の施設の原データ・安全性未確認に関する情報は削除しない。PCも最大36dvh/285px。
- フローは自動再生ではない。「比較」押下でAへ移り、以降は観客/発表者が各ステージへ進める。実際の開設状況、洪水安全性、現地移動条件は表示・推奨しない。

**Required gate:** exact-head required `test`、GISの実Chromiumテスト（PCと390pxモバイル）で、各ステージの1カード、A/B/結論ボタン、段階番号、タブの押下状態、地図内A/Bマーカーの存在、結果パネルの高さ上限を確認する。実機Safari・観客の視線誘導は依然として人間受入待ち。
