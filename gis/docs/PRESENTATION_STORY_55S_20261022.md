# HINANEX GIS — 発表用55秒ビジュアルデモ（E / 2026-10-22）

## ユーザー検証から変更した方針
元の90秒版では、右側に長い説明が次々と出るだけで観客が見どころを把握できなかった。**地図を動かすだけでは価値は伝わらない**。発表の主役を「原本と抽出の対応」「証拠不足で建物を確定しない」「合成不正入力を拒否する」の三つの視覚変化に移し、55秒へ短縮する。

## 公開UI
GIS /gis/gis/ →「場面」→「発表用ガイド付きデモ」→**55秒で検証の流れを再生する**。GIS右側（スマートフォンは下部）のビジュアルパネルに、一つの見出し・3ノードの関係図・一つの結論だけを大きく表示。プレゼン中のマーカーは視覚的に控えめにするが、元の地図データ・レイヤー設定は変更しない。

従来の**詳細90秒版**（PR #231/#232）は残す。55秒版の「詳細90秒版で根拠を見る」から切り替えられる。Bの独立した詳細資料ページと旧3地域ツアーも維持。

## 55秒の再生台本
| 時間 | 見せるもの | 断定しないもの |
| --- | --- | --- |
| 0–5秒 | 対象の江戸川区・公式原本→HINANEX→C監査の流れ。既存の元座標付き**現行**D施設があれば地図が移動 | 2019年の避難先・浸水進行 |
| 5–18秒 | 公式66明細→HINANEX65運用グループ/66明細→**T0機械照合PASS** | 予測MATCH・Cの人手as-of承認 |
| 18–34秒 | **通常205人＋夜間11人→実際に使用した建物「？」→承認0件／比較不可** | 未確認の場所を地図ピンへ置く・予測ABSTAIN成功 |
| 34–48秒 | **合成の不正入力→無根拠の建物確定・夜間明細欠落→独立Cの負系テストが拒否** | 実際の予測MISMATCH |
| 48–55秒 | **正しく読む／決め付けない／誤りを拒否する** | 危険度・避難推奨・予測精度 |

既存C JSON（/evidence/2019_edogawa_evidence_cases.json、C #226/Shared #227）のフラグと3ケースを既存Eの厳格バリデータで検証し、更に数字・合成・nullの必須文字列を確認してから再生する。読み込み・データ検証失敗時はfail closed。地図移動は共有済みHINANEX_PRESENTATION_TOUR.focus("13123")を利用し、**実座標のある現行D情報のみ**。避難先建物は新規に特定しない。

事後の公式報告の意味は変更しない：T0機械的整合≠予測一致、T1 NOT_EVALUABLE≠予測ABSTAIN成功、合成負系テスト≠実災害MISMATCH。C人手の2019 as-of承認は未了。現行Dマーカーは2019当日の位置を示さないことを常時記載。

## 手動操作と検証
ケース①/②/③へのジャンプ、停止/再生、次へ、最初から、Esc、原本とC監査ログへのリンク、詳細版への切替。タブが隠れたらタイマー停止。地図を手動で操作すると再生を停止し、閉じる際にユーザーの地図の視点を保全。古いC非同期レスポンスは再生を復活させない。

CIのE Nodeテストは55秒の分割時刻、シーンごとの意味、地図API呼出し、C失敗時停止、操作、旧90秒版への切替を対象。実Render上のマーカー/タイル/描画は、CI成功でも「受入済み」とはしない。

### 2026-10-22発表前の実機チェック
1. 発表PC/Edgeで、GIS画面から55秒再生ボタンを選択し、別タブに飛ばないことを確認する。
2. 公式原本とCデータが読み込まれてからだけ再生が始まり、可能ならDの実座標で地図が動くことを確認する。
3. 3ケースの数字・「？」・「拒否」が少し離れた画面から視認できるか確認する。
4. 2019年の避難先ピンを新しく出していないか、現行Dと当日避難先の違いが分かるか確認する。
5. 55秒自動完走、途中停止/手動スキップ、90秒版切替、元のGISへ復帰を確認する。
6. モバイルで半画面以下に説明が収まり、地図が操作できることを確認する。
7. 7分通しの発表を1回録画し、テロップの視認性と説明のタイミングを評価する。
