## 1. 企画意図と混同しない概念

発表者がライブで「HINANEXでできること」を見せるだけでなく、観客が自身の端末で探索・根拠確認できることを最重要の体験にする。

**配布して触るもの**と**発表者が自動で見せるもの**は別の入口とする。

| 概念 | この発表での役割 | 既存GISとの関係 |
| --- | --- | --- |
| 観客アクセス | 画面上のURL・QRから観客各自のスマホで通常の地図を開く | GISのURLを配る。観客に自動でGPS許可や検索を実行しない |
| ガイド付きデモ（自動ツアー） | 公式・検証状況を説明するナレーション付きの決められた地図移動/表示ステップ | **発表用の閲覧演出**。時間経過や実災害を算出しない |
| 場面 | 将来的に災害前／災害後／避難経路など画面構成そのものを切替 | 未実装の場面は表示予定のまま。自動ツアーを「災害シミュレーション」と呼ばない |
| シナリオ | 地点・公式掲載情報の照合や災害種別条件の探索 | 既存の平時公式情報探索を維持。実災害/予測と混ぜない |
| データ状態 | D施設＝RegionExport、GSI公式掲載＝C検証対象、背景・洪水ラスタは別Source | 単なる演出によって出典、UNKNOWN、未確認・未取得を変更しない |

**禁止する主張：**「安全な避難先」「開設中」「あなたはここへ避難」「災害発生後の予測」「地域内の全施設」など。観客に誤解させる仮想の避難経路・ハザード着色を描かない。

## 2. 画面・導線

### 2-A. 発表者：共有・体験入口

- ヘッダーの「共有・体験」または「場面」内の発表向け導線から、**URL表示／QR表示** の小型シートを開く。PC投影の読み取りを前提に、正方形のQRは十分な白余白、短い説明と直接URL、コピーを一画面内に納める
- QRが表す正本URLは `https://hinanex-staging.onrender.com/gis/gis/?demo=audience`（仮、10/22使用環境を確定後に固定）。主画面をそのまま開ける。**観客端末で勝手に自動ツアーを開始しない**
- 自サイトで生成/同梱するQRを使用する。外部QR APIへURLを投げたり観客GPS・個人識別子・利用状況を送信しない。QRと文字列URLは**完全一致**させる
- 発表者はQRを見せたまま止められ、×、Esc、外側タップで閉じる。既存上部4カード・設定・施設詳細と排他的に開く
- `/frontend/` の「分析・根拠 ↗」は別タブのまま維持。詳細根拠を調べたい観客も利用できる

### 2-B. 観客：スマホからの初回体験

- 取得URLを開くと通常のマップを表示する。観客向け小さな案内「施設マークをタップ→元情報を読む」「探索したい地点を指定→公式掲載参照」「データがない＝安全ではない」を1度示し、すぐ閉じられる
- 初期設定は視認できる通常の地図と既存レイヤー。地図のスクロール/ピンチ/施設カードが操作可能。パフォーマンス設定、既存の明示的なGPS同意動作は変更しない
- 過度なアクセスがRender/外部タイルのボトルネックになる可能性を発表前に確認する。**QRを載せる＝安全性や稼働率を保証**ではない
- プロジェクター上にはQRと短URLを両方表示し、読めない場合はURL手入力、回線が使えない場合は事前録画したデモへ切替
- ブラウザ/配信先へのタイルアクセスから大まかな閲覧地域が分かり得る旨は既存の注意書きを維持。観客の入力や位置情報の取得同意なしにGPSを実行しない

## 3. 自動デモツアー：まず「説明可能な地図移動」を作る

### 3-A. MVP候補「3地域のデータの違いを見る」（2〜3分以内）

デモは発表者が**明示的に開始**し、ガイドカードに現在の手順/進捗を表示。自動的に地図を滑らかに動かし、既存の確認済みデータが実際に読み込まれるところを見せる。各地点の表示は**データあり/なしで表現を変える**。

1. はじめに：タイトルと注意書きを出す。「これは防災情報の探索デモ。実災害予測・避難指示ではない」
2. 江戸川区：**既存REGION_CONFIGSの表示領域へ移動**。Dの座標付き施設を見せ、地図内カードから元資料・出典を確認できることを説明する。未取得なら明示して次へ
3. 新潟市：地図の移動で自動的に座標確認済みDマーカーが表示される実装を見せる。Niigata ODSの`○/×/－`・利用階の洪水適合はIssue #48で未確定、**UNKNOWNのまま**
4. 名古屋市：取得レコードが存在してもソース座標がないときは位置を推測しない、という限界をカードと既存施設一覧への導線で説明する（自動で架空のピンは描かない）
5. 終了：基本マップ操作に戻り、観客のQR体験と「分析・根拠 ↗」への導線を促す

**注意：** 都市の中心座標だけで公式施設や市域の安全性を推論しない。ツアーのカメラ位置は現在のUIで採用済みの`REGION_CONFIGS`の表示用中心／出典のある施設boundsだけを利用し、新たな擬似施設位置を作らない。

### 3-B. 操作状態遷移

`idle → preparing → playing(step) → paused → playing → completed` または `stopped/error`。

- UI: 「デモを開始」「一時停止／再開」「次へ」「停止」「閉じる」。進行はステップ単位、文章は元情報と限界を含む
- 地図操作（ドラッグ、ホイール、ピンチ）、通常地域ショートカットや施設カード操作があれば**自動ツアーを一時停止**し、ユーザー操作を優先。Escや停止では即座にタイマー・移動アニメーションを止める
- カードの自動開閉・GPS要求・外部リンクの自動クリック・自動で危険度や安全な経路を計算する機能は含まない
- `prefers-reduced-motion` を尊重し、該当時はアニメーションなしの即時地図移動。画面読み上げのためステップ見出しをテキストで提供、過度なaria-live連続発話は禁止
- `map.flyTo` / `setView` は**自動ツアーの明示的開始中だけ**。既存閲覧範囲連動のD表示と競合しないようステップ遷移を逐次制御。停止後は直前の地図中心/ズーム/レイヤー設定へ復帰する選択肢を提供
- デモ演出は固定パターン定義（順序/カメラ/文章）のみ。出典確認状態や対象regionのHTTP状態は都度検証し、未取得時に架空の成功演出を表示しない

### 3-C. 拡張候補（10/22の保証範囲外）

- 公式GSI参照の地点探索デモ（Cが独立検証した地点と元URLでのみ動作）、分析結果↗との連動、録画スクリプト連携
- ユーザーが「場面」を選択して災害前/後/避難行動を見比べる*将来の*時系列シミュレーション
- 任意のデモパターン編集ツール、ブラウザ間同期、観客操作ログ、個人の事前登録や避難経路計算

## 4. 非機能・性能・安全

- 既存マップの操作感とズーム限界、GIS/Frontendページ独立性を維持。再取得は既存キャッシュ活用（施設マーカー描画だけでAPI連続要求しない）
- 有効なデータ取得失敗/UNKNOWN/表示限界を消さない。地図外・施設0件を「安全」や「施設なし」と誤認させない
- デモ視点変更は公式洪水ラスタ取得を減らしたい場合も、レイヤーを自動無効化して無被害に見せることはしない。失敗時は明示
- QRの静的な実URLと直接URLを照合し、スマホEdge/Chrome/SafariとPCブラウザでHTTPS起動を確認。発表会場Wi-Fiが外部サイトを許可するかも確認
- 同時アクセス目標は**本番前の検証結果で決定**。測定していない人数・外部タイル可用性を保証しない
- audience用 `demo=audience` は画面案内の表示にのみ使用、他の画面/検索APIの安全判定を変えない。観客と発表者でURLに個人識別子を埋め込まない
