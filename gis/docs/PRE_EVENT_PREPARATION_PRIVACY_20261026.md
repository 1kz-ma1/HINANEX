# HINANEX 事前入力の任意端末内保存・削除モジュール（2026-10-26）

状態：**E内部 Prototype / UI未接続 / 利用同意画面なし / DRILL・LIVE非接続**

## このPRで実装する仕様
- 地域（5桁市区町村コード）、利用階（整数1～200、未回答null）、上階へ移れるか（true/false/null）の**3項目のみ**。値は自己申告であり、建物や自宅が安全だという根拠にはならない。
- `createStore(storage)` は何も読み書きしない。本人が選んだ場合だけ、UI側から明示的な `save(profile, { consentGiven: true })` を呼べるようにする。アプリ起動時の自動保存や位置情報取得を行わない。
- 読出し `read()` と削除 `deleteSaved()` を明示的に分離。古いデータ（180日超）や未来時刻・スキーマ不一致は利用せず、削除を別操作で実行できる。
- 許可されたキー以外はすべて拒否。氏名・住所・緯度経度・健康情報・連絡先・同居者・GPS・自動計測値は永続化しない。保存先は独立名の `hinanex.gis.pre_event.optin.v1` のみ。
- Safariのプライベートブラウズ等で保存が利用できない場合は明確な結果を返す。削除が失敗した場合は成功を返さない。確認・削除が行われた証明や暗号化は提供しない。

**重要:** ブラウザ `localStorage` は暗号化された秘密の保管庫ではない。同一オリジン上のJSがアクセスでき、端末の共有・XSS・ブラウザ同期・バックアップ等による漏洩を完全に防げない。そもそもこのPRでは**画面からアクセスできるようにしない**ので、実運用での法的同意やユーザー操作は成立していない。静的Webへロードするには、ユーザー向け保存範囲・説明・同意・削除UIを別レビューしてから行う。

4. 各プロファイルの位置精度・有効期限・運用時のプライバシー審査。
