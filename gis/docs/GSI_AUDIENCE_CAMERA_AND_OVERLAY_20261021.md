# E / GSI公式掲載地点の発表デモ — カメラ制御と重複UI修正（2026-10-21）

## 概要とユーザーからの症状

`/gis/gis/?demo=audience` の江戸川区デモにおいて、GSI紫ピンの公開情報を見せると自動的に千葉県側へ地図中心が動いた。また、デモ上部の場面案内、過去に開いた2地点比較パネル、Leaflet地点詳細ポップアップが同時に重なった。

## CURRENT / 根拠ある原因

- 既存の `window.HINANEX_GSI_FLOOD_PRESENTER.show()` は `setDisplayMode("nearby")` の直後に `focusReferenceCandidates()` を実行。後者は検証済み紫ピン最大5件と元の探索地点の外接矩形に地図を `fitBounds` する。この矩形は自治体境界ではなく、千葉県側を含みうる。
- `selectFromMap()` は `inspect()` 経由で `flyTo(...,14)` を行っていたため、手動でピンを選んでも追加のカメラ移動が発生。
- 公式掲載地点のポップアップ `detail()` は `autoPan: true` のため、ポップアップの画面内確保でも地図が動きうる。
- デモ開始時、他のプレイヤーは閉じるが、通常操作から残った2地点比較とLeafletポップアップは閉じていなかった。

## 今回変更したUX

1. **自動移動停止:** 場面02で検証済みGSIピンを表示するが、カメラはそれらへ自動移動しない。開始時は、選択した自治体のD原レコード座標または利用者が明示的に選んだ探索地点を文脈地点とする。GSIデータがない場合は既存の未検証・未配信表示を維持。
2. **明示的な地点移動:** 場面03で、既存の再生ボタンを `紫ピンへ` に変え、利用者が**自分で押した場合に限り**検証済みGSI地点へ視点を移す（千葉県側を含む場合があるとaccessible name/tooltipに明示）。ボタンは検証済みの紫ピン選択を代行しない。利用者による紫ピンのクリックを必要とする場面03の状態遷移は従来どおり。
3. **選択時に追いかけない:** verified pin selection は従来の出典/住所/traceを返すが、カメラをさらに `flyTo` しない。デモ中に開くGSI詳細ポップアップの `autoPan` も無効化。それ以外の通常地図ポップアップは現状どおり。
4. **重複カードを避ける:** デモ開始時に既存の2地点比較パネルと現在のLeafletポップアップを閉じる。デモ進行中は2地点比較の再オープン操作を受け付けない。終了後の探索時には従来の検証済みデータの表示へ復帰する。

## 防災データの境界（変更なし）

- GSI `skhb01` 掲載地点と江戸川区の自治体施設データ（D）を同一施設と扱わない。
- 隣接県の公式掲載地点を架空の江戸川区内施設に変換したり、除外したりしない。
- 未検証タイルの欠如は「避難場所が存在しない」「洪水に安全」を意味しない。
- 現在の開設・混雑・移動安全性・公式指定時点・経路探索・洪水適合性の判定は増やさない。
