# HINANEX スマホ地図UIの小規模改善・受入メモ（2026-10-23）

## 目的
新規メンバーの初回利用フィードバックに対して、**押しやすさ・読みやすさ・表面の情報量**のみ調整。ダークテーマ、主役の地図、地域データ/判定、出典と未評価を伝える安全上の注意は保持する。

## 変更（E領域のみ）
- `gis/gis/index.html`: 地図の場面・シナリオ・マーク・災害情報の説明を短くし、将来のシミュレーション/経路機能や未提供レイヤーの詳細説明を、既存の「根拠・確認状況」パネル内の折りたたみ節へ移動。既存のB側 `分析・根拠` リンクを利用し、**分析ページを複製・新設しない**。
- `gis/gis/css/map_first.css`: 幅680px以下の4メニュー48px以上、共有と分析リンク44px以上、メニュー内主要タップボタン44px以上。ラベル12px中心、狭い幅では不要な装飾矢印を隠す。画面下の将来予定項目は暗過ぎるopacityを解除し、`予定` と非対話 `span` を維持。
- 背景マップ、Leaflet、公式資料の表示内容、ハザード色分け、GPS、共有URL/QR動作、D契約、RegionExport等は変更なし。安全の注意書きと出典への到達経路は維持。

## 安全性
- `地図` 以外の下部 `やること`・`マイ情報` は**非対話の予定表示**のまま。押せる機能として偽装しない。
- `予測・経路案内は未提供`、`安全性は未判定`、`未取得は安全を意味しない` の各注意は短い表面表示に残し、細部を折りたたみ＋分析リンクから確認可能にする。
- 出典、公式の意味、安全性の判定、位置の承認を変更しない。

## 受入テスト
1. 自動: `node gis/tests/map_controller.test.js` を含むGIS回帰。GitHub Actions Required `test` が成功すること。DOM文言とCSS定義が存在する静的検査は**実ブラウザでのタッチサイズ測定ではない**。
2. 実機（未実施）: iPhone Safari／Android Chromeを幅320/375/390/430pxとランドスケープで確認。4メニューおよび共有・分析で実際の `getBoundingClientRect()` の幅/高さが44px以上、フォーカス移動、メニュー開閉、外側タップ、地図パン／ズーム、共有QRコピー、下部ナビとiOS safe-areaを確認。
3. 320pxでヘッダーのHINANEXロゴ、共有と分析が重ならないこと。文字拡大時もクリップしないこと。将来予定項目が誤って押せないこと。
4. メイン地図を見たときにデバッグ文言が主役にならず、必要時だけ詳細が見られることをメンバーに再確認。

## 作業終了の判定
本PRはEのHTML/CSSと静的回帰に限定する**UI調整の最後の小規模PR**とし、大型の見た目改修を連鎖させない。実機QAで重大な重なりが見つかった場合だけ最小限の修正。mainへのmergeはユーザーのMerge Captain確認の後。
