# HINANEX GIS — 同一地図の「通常表示 / シナリオ探索」軽量タブと最新Bデザイン統一案

- 作成：2026-10-09
- ステータス：**DESIGN PROPOSAL / 未実装**。この文書をCIが承認しても新UIの実機受入完了にはならない
- 実装対象：E `gis/**`（B `frontend/**` のスタイルは**閲覧参照のみ**）。`main` 統合はMerge Captain判断
- 前提：実機でD3地域のRegionExport v0.9読込、GSI `skhb01` C照合済みタイルの地図表示、Dクラスタ・比較・GPS拒否時の手動座標入力を確認済み

## 意図と今回合意したUI方向

GISを2ページ・2アプリに分離しない。**同じLeaflet地図・同じ現在地/ズーム/3地域Dデータ/GSI C検証済み結果を維持**しながら、画面上部の軽いセグメントタブで

- **通常表示**：既存の地図閲覧・レイヤー・施設原値詳細を優先
- **シナリオ探索**：同じ機能に「地域を確認 → 起点を指定 → 検証済み情報を確認 → D/GSI比較」という操作ガイドと進行状態を添える

を切り替える。切替は見せ方・操作パネルの優先順位だけを変え、評価エンジンや災害シナリオを実行・再計算したふりをしない。将来の洪水時系列シミュレーション・適合性判定とは明確に区別する。

### デザイン正本：新しいB frontend

E旧GISのライトブルー白3カラムには寄せず、現行B `frontend/styles.css`（2026-10-09参照時点）から**新しいデザイントークンと構成原則**をEローカルのCSSとして採用する。BのCSSを直接読み込まない（BのコンポーネントセレクタとEのLeafletが衝突しないようにする）。

| 用途 | Bの現行トークン／値 | Eでの意図 |
|---|---|---|
| 基本背景 | `--bg: #07131e` | 画面外枠、余白 |
| サーフェス | `--surface: #0d1c29` / `--surface-raised: #122636` | サイドバー、結果カード、探索ステップ |
| 文字 | `--text: #edf8fb` / `--muted: #91a9b5` | 視認性・根拠説明 |
| 主アクセント | `--cyan: #4ed7dc` | 選択タブ、探索の次の操作 |
| 補助 | `--green: #62d7a4` / `--amber: #f5bd72` / `--violet: #b9a8ff` | 状態・出典・不確実性。ただし**地図の色意味を勝手に変えない** |
| 線 | `--line: rgba(181,216,229,0.14)` | 過度な囲い込みを避けた分割 |

**地図部分だけは公的洪水ラスタの色を改変しない。** GSI背景地図をdarkフィルター・色相反転・opacityや独自危険度パレットで加工しない。暗いアプリChrome + 無加工の公的タイル + アクセシブルな情報カードという構成。D緑／GSI紫／青起点の地図マーカーも現行の出典区別を維持する。

## 最小UI構造

```text
┌ HINANEX  GIS / Flood Explorer ──────────────────────┐
│  [ 通常表示 ] [ シナリオ探索 ]   地域：江戸川区         │
├──── 左 / 探索・レイヤー ───┬──── 地図 ──┬─ 右 / 根拠 ┤
│通常: 施設表示・レイヤー     │             │選択地点/施設│
│探索: 「次に確認すること」   │  Leaflet    │確認できた事実│
│地域→起点→照合→比較        │  同一Map     │不明/未取得   │
│                            │             │出典の区別   │
├───────────────────────────┴───────────┴──────────┤
│ 災害時の行動指示ではない。最新の自治体公表を優先する     │
└────────────────────────────────────────────────────┘
```

- タブはヘッダー直下。**通常表示を初期値**とする。切替はDOM panelの`hidden`と`aria-selected`、焦点管理などの表現のみで、`L.map`の作り直し・`selectRegion()`・`clearReferenceDiscovery()`・再fetchを呼ばない。
- **既存のD/GSI/both**は別の「施設レイヤー表示モード」で、タブとの二重管理を避ける。探索タブへ入るだけでレイヤー・起点・縮尺・GPS状態を自動変更しない。
- 右側の根拠パネルは両タブの共通コンテンツ。探索時は「確認できたデータ」「不明・未取得」「出典／Evidence」へ視覚的に分節するが、情報量や事実関係を削減しない。狭い画面では開閉ドロワー等を検討し、情報を永久に隠すことは避ける。
- 高度なレイヤー設定／JSON読み込みは「詳細設定」で開閉可能にし、発表時の探索メイン画面に大量のチェックボックスを露出させない。旧UIの操作手段はすべて維持する。

## 探索進行＝UI状態（災害リスクの進行ではない）

| 表示ステップ | 実装済み情報による判定 | 未完了時の文言 |
|---|---|---|
| 1 地域の確認 | `selectedRegionCode` が既知3コードで、ロード状態を別途明示 | 「地域を選択してください」|
| 2 起点の指定 | ユーザーが座標/地図/GPSで`selectedOrigin`を指定 | 「調べる地点を指定してください」 |
| 3 公式掲載情報の照合 | 既存C-accepted catalogの`verifiedTileCount`と要求タイル数に基づく**取得結果**。9/9であっても避難の安全性を意味しない | 「検証済み参考情報が未取得／照合待ちです」 |
| 4 情報の比較 | `displayMode === "both"` かつD実座標とGSIの両方がある場合は**同画面表示できる**。出典・地理的範囲が異なることを明記 | 「比較できる座標データが揃っていません。施設一覧／出典を確認してください」 |

進行は**ユーザーの操作と既存モデルの状態から導出**する。クリックだけで検証済み状態を付与しない。エラーや欠損で「次へ進めない」状態でも、通常表示タブへ戻る操作を妨げない。時系列の浸水波形、避難経路計算、勝手なランキングは作らない。

### 既知のエッジケース

1. **名古屋市**：D 1602件全件座標欠損の場合、従来の施設一覧への切替と`UNKNOWN`を保つ。探索ステップで「比較不可能」を明示し、無理にマーカーを作らない。
2. **公的洪水ラスタの部分欠損**：確認済み実例`/8/228/101.png`への直アクセスは配信元の`ObjectNotFound`。画面上に「ラスタの一部が取得できない／浸水なしではない」と残す。Cの`skhb01`ソースが9/9 acceptedであっても、ラスタの完全取得を合格に変換しない。
3. **GPS拒否**：手動緯度経度の導線を探索モードにも常設。許可拒否で進行をリセットしない。正確なGPS座標はURLやTelemetryへ保存しない既存仕様を継続。
4. **切替・戻る**：両タブで共有するLeafletマップ・地域・起点・D/GSI参照・元情報・ズームを保つ。狭い画面でDOMの可視性を切り替える場合、必要に応じて`map.invalidateSize()`だけ実施する。
5. **アクセシビリティ**：タブに`role="tablist"`、`role="tab"`、`aria-selected`、キーボード操作、見出し階層、単独の色だけに依存しないsource表記、`prefers-reduced-motion`を適用。アニメーションは状態の説明を補助する短いトランジションのみ。

## PR分割（10/22デモ優先、D/Cに触れない）

1. **E-1 軽量タブと最新Bテーマの整合**：E HTML/CSSの骨格更新、既存マップの1インスタンス維持、タブ往復で地図状態が不変、画面幅・地図タイルの色不改変を回帰テスト。
2. **E-2 探索ガイド＆根拠カード**：進行状態は既存の`map.js`の実情報だけで導出。UNKNOWNとCタイル検証率を区別。GSI未掲載/未検証は「施設なし」に置換しない。
3. **E-3 発表リハーサル**：名古屋の一覧、GPS拒否、C既存2地点9/9、比較地図、独立ラスタ未配信警告の操作を録画・時間計測し、台本更新。**デモが完了したと言うのはユーザーの実機合格後**。

### リリースゲート

- `main`へのマージ禁止。各PRは`integration/flood-scenario-preview`のみを対象にし、CI greenかつ実機への反映確認を独立管理する。
- B `frontend/**`のデザイントークンはEで参照するだけ。変更は`gis/**`限定。B/共通デザインの本格的共有化は別件。
- ユーザーが求めるのは**「シナリオ探索タブを押せるほど軽い切替」**。別ルート・別マップ・データ自動リセット・独自災害予測を導入しない。
- 実災害時の開設・安全性・経路・リスク判定は未検証であり、`Scenario`という名称を採用しても防災上の判断の保証にはならない。
