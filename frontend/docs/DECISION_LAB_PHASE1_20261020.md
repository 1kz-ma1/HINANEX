- 既存 `main` 上のA/C/D/Eの実装・RegionExport Schema・GSIデモを変更せず、`frontend/decision-lab.html` にユーザー操作を試せる独立した画面を追加する。

- /frontend/ のヘッダーから試作へアクセスできる（本番地図のUIやデータには変更なし）。
- 検証用であることと現時点の未認定状態を画面に常設表示する。

## PRODUCT TEST: 実ユーザーに確認すること
1. 30秒以内に、江戸川区の「待避施設」と早期の広域避難が同じ意味でないことに気づけるか。
2. 「GSI掲載地点」と「区の待避施設」の異なる根拠を自分でたどれるか。
3. 施設の開設・安全・距離による優先順位を画面が保証していると誤認しないか。
4. 390px幅の画面で項目を選び、公式リンクを開き、比較メモを確認できるか。
5. 不要な説明やカードが操作を阻害しないか。

結果は定性的な観察として記録する。テスト人数や成功率を測定していない段階では「ユーザー検証PASS」と記載しない。

## CURRENT: Phase 2 / 利用者が問いと2資料を選んで比較（2026-10-20）

- Phase 1のすべてのソースカード・原文リンク・自己申告チェック・比較メモは維持。
- 利用者が以下の情報探索目的を選択できる：制度・役割、所在地/名称、洪水時の個別条件、現在の開設、移動経路の安全性。
- 利用者が別々の2出典を手動選択し、同じ画面で各資料の説明対象とリンクを横並び（モバイルは縦並び）で比較できる。
- 問いごとに「確認の視点」「この画面では未確定」を明示。未承認の施設ID結合・GSI対自治体の一致判定・安全評価・スコア・距離・経路生成はしない。
- 両資料が同一、または未定義の場合は比較内容をクリアして明示的なエラーを表示し、メモへ不正な比較結果を保存しない。
- 入力は画面内メモにのみ反映し、個人位置/GPSの取得、外部API通信、レビュー承認投稿を行わない。
- 資料の説明対象と未確定情報は**プロダクト検証用の固定説明文**であり、自治体/GSIサイトを毎回解析した結果ではない。
- 2027-02-09 MVPの個別施設条件→候補比較→選択→参考経路は**まだ未実装**。現段階の比較対象は施設ではなく「異なる公式情報源」。

## Phase 2 UX acceptance criteria（手動未確認）
- 390pxで2資料が重ならず縦並びとなり、いずれの一次資料リンクもタップできる。
- "今開いているか" を選んでも、現在利用可能と保証する文面が現れない。
- "安全な経路があるか" を選んでも、距離・所要時間・経路を捏造しない。
- 同じ資料を左右で選ぶと比較結果を消し、異なる資料に戻すと表示が復帰する。
- 意味、施設同一性、洪水適合、開設、経路の5問で未確定理由が変化する。
- 自分で原文を確認したというチェックが、正式A/C承認にならないと理解できる。
- 画面を閉じて再開した際、前の利用者の選択内容は引き継がれない。
- 実際にユーザーが理解しやすいかは、DOM/単体テストの成功だけでは検証できない。
