## 起動手順

このフォルダの `index.html` をブラウザで直接開く。外部依存・ネットワーク接続・ビルドは不要。

またはリポジトリrootでHTTP配信する場合:

```powershell
python -m http.server 8000
# http://localhost:8000/frontend/prototypes/f02-shelter-explore/
```

受領ZIPを解凍してそのまま開いても試作できます。

## できること

1. 架空の「青地区」「橙地区」「空白地区」を選択する（実在自治体との混同を避ける）。
2. 施設名で検索する（全角・半角カタカナを正規化）。
3. 座標なしの施設も一覧に含める。件数は全記録・検索結果・座標なし・資料未取得を分ける。
4. 施設の詳細に施設名・架空住所・区分・災害原記号（意味は解釈しない）を表示する。
5. 資料ラベル、fixture版、公開/更新日未確認、元資料未取得を区別する。
6. 指定・敷地/入口・災害ごとの条件・開設・正式範囲の確認状態を分けて表示する。
7. スイッチでデータ読込失敗（**シミュレーション**）を再現し、データ0件、検索0件と別に表示する。
8. ネイティブボタンでキーボード操作、選択時に詳細見出しへフォーカスを移す。

## 動作確認シナリオ

- 通常：青地区で施設4件表示。施設を選択すると出典と未確認事項を表示。
- `UNKNOWN`：すずらん交流室の役割と災害区分は未確認。
- 座標なし：すずらん交流室・木かげ文化会館は一覧から除外されない。
- 元資料未取得：木かげ文化会館の出典欄に専用表示。
- 地域0件：空白地区を選択。
- 検索0件：青地区で「該当なし」を検索。
- エラー：表示ケースを「データ読込エラーを再現」に変更。

## リスク・後続の設計相談（提案のみ）

- このfixtureの形をD Contractに流用しない。Dが提供する施設・根拠・位置精度・状態別フィールドを別途確定してから、B側の表示マッピングを設計する。
- `UNKNOWN` / `NOT_FOUND` / 座標欠損 / 取得失敗 / 開設未確認を別々に保持し、根拠の無いデータを補完しない。
- 将来、出典の版・取得日・公式の対象災害・指定範囲の境界や入口・人間確認の状態を表示するには、D/Cとの契約確認が必要。
- 本作業はfixtureのみ。既存D Contractに対する変更提案は文書化にとどめる。

## 2026-11-11 HTTPブラウザ回帰（受領後の追加検証）

F02の独立試作は`tests/f02-http-browser.test.cjs`から、Chrome/Chromiumを実際に起動し、Node標準`http`で配信した**独立HTML/CSS/JSファイルをHTTP経由で読み込む**E2Eテストを追加した。従来の`page.set_content`のモック検証とは異なる。

- GitHub Actions のrequired `test`にある`B Frontend tests`（`frontend/npm test`）で自動実行。実ブラウザが見つからないCIやURL遷移が遮断されたCIは**失敗扱い**とする。
- 単体で実行する場合：`node --test tests/f02-http-browser.test.cjs`。Chromeのパスを明示するには`F02_BROWSER_BIN`を設定する。Chrome未導入の開発端末では当該テストのみSKIPとする（CIでのSKIPは認めない）。
- チェック対象：HTML/CSS/JS5ファイルのHTTP読込・安全注意、合成施設の一覧・詳細とUNKNOWN、選択ボタンへのフォーカス復元、検索、記録0件・検索0件・模擬取得エラー、320/390/1440pxでの横はみ出し、JS例外・外部API呼出の禁止。
- 自動Chrome確認は物理タッチ、Safari/Android端末、スクリーンリーダー、実在データの根拠承認ではない。ここで完成UIとみなさない。
